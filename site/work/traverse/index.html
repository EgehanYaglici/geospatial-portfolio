01What it does

WebGIS Road is a browser-based road quality issue tracker and geometry editor for Barcelona. Three field editors, each responsible for a neighbourhood (Eixample, Gràcia, Ciutat Vella), can log in, browse open tasks in the left panel, click any task to zoom the map to the affected road segments with an orange highlight overlay, and take ownership with a single button. The map pin immediately turns yellow and shows the assignee's initials: visible to every other user via 20-second polling.

On top of the geometry editor sits a full task management system. Any supervisor can create a work order tied to one or more road segments, assign it to a team member, and track it through a four-state lifecycle. Every mutation writes to an task_activity audit table, so the timeline of every job (who created it, who picked it up, every status change) is always visible.

04Features
Live MVT vector tiles
PostGIS ST_AsMVT served over FastAPI. Tiles refresh after every publish. Road colour and width vary by highway class and editability at every zoom level.
Task state machine
Four states with typed transitions: pending → in_progress → done / rejected. Every mutation writes to a task_activity audit table. Full history visible in the Activity tab.
Map task pins
Each task places an SVG teardrop pin at the midpoint of its road segments. Grey = pending, yellow = in_progress. Done and rejected tasks hide their pins. Assignee badge shows initials: blue for self, purple for others.
Multi-user with real-time polling
JWT auth, three editor accounts, per-area assignment. Task assignments poll every 20 seconds: pin colours and assignee badges update across all open sessions automatically. No WebSocket needed.
Vertex editing + snapping
Drag existing vertices to reshape roads. Midpoint handles insert new vertices. Snap-to-road within 14 px. Ctrl+Z undo history. Saves to a local changeset before publishing.
Changeset review + publish
All edits staged locally before committing. Review drawer shows each pending change (new / modified / deleted). Single publish call batches them to the backend, refreshes tiles on success.
05Technical stack
Frontend React 18 + Vite + TypeScript, single-page app. MapLibre GL JS for all map rendering. CartoDB Positron basemap. maplibregl.Marker for SVG teardrop task pins. Inline styles, zero CSS-in-JS overhead.
Map tiles PostGIS ST_AsMVT → FastAPI → MapLibre. Token-authenticated MVT endpoint at /api/tiles/{z}/{x}/{y}.pbf. Sub-80 ms tile latency at zoom 14.
Backend FastAPI + SQLAlchemy async + asyncpg. Task endpoints (list, detail, status, assign). Road geometry endpoint for highlight overlay. Demo reset endpoint. Raw SQL for tile generation.
Auth JWT Bearer token stored in localStorage. Three area editor accounts. Token validated on every API request. 6-second timeout; 401 response clears token and returns to login.
Database PostgreSQL 15 + PostGIS 3. roads table with geometry(LineString, 4326) + attributes. tasks table with jsonb road_ids array. task_activity audit log. GIST spatial index on road geometry.
Data OpenStreetMap Barcelona extract via Overpass API. 170,688 road segments covering three named neighbourhoods, imported with geometry and OSM attributes preserved.
06Design system

Light-first UI: #F8F9FA page background, #FFFFFF panel background, #E5E7EB borders. Both fixed panels (300 px left, 360 px right) use position: fixed and all map zooms use panel-aware padding so selected roads are never hidden behind the UI.

Status colour encodes consistently across every surface: task list cards, map pins, and detail headers. Map pins are teardrop SVGs: grey for pending, yellow (#F59E0B) for in_progress, hidden once done. Assignee badge on the pin is blue (#2563EB) for yourself, purple (#7C3AED) for another user's tasks.

08Bugs found and fixed in production

Four issues caught after deploying to EC2 and testing live at clearway.rasterlayer.com. Each fix below shows the exact change made.

TaskDrawer overlaps TopBar on open TaskDrawer.tsx
- position:"fixed", right:0, top:0, bottom:0, width:420, zIndex:50
- <div onClick={onClose} style={{ position:"fixed", inset:0, zIndex:49 }}/>
+ position:"fixed", right:0, top:52, bottom:0, width:420, zIndex:50
+ <div onClick={onClose} style={{ position:"fixed", top:52, right:0, bottom:0, left:0, zIndex:49 }}/>
TaskDrawer started at top:0, covering the 52px TopBar (z-index 40) because the drawer was at z-index 50. Backdrop also blocked TopBar interaction. Changed both to top:52.
Task pins drift during map zoom Editor.tsx mkTaskPin()
- <svg style="filter:drop-shadow(0 2px 6px rgba(0,0,0,0.5));overflow:visible">
+ <svg overflow="visible"><defs><filter id="ps-...">
+ <feDropShadow dx="0" dy="2" stdDeviation="2.5"/>
+ </filter></defs><path ... filter="url(#ps-...)"/>
CSS filter on the SVG root creates a GPU stacking context that conflicts with MapLibre's transform-based marker positioning during zoom animations. Moved the shadow to an SVG <filter> applied only to the path element, which doesn't affect the marker's layout bounding box.
Road drawing lags with 170k loaded roads Editor.tsx mousemove
- map.on("mousemove", (e) => {
- const visualSnap = getVisualSnapPoint(map, e); // on every event
+ pendingSnapEventRef.current = e;
+ if (snapRafRef.current === null) {
+ snapRafRef.current = requestAnimationFrame(() => {
+ const visualSnap = getVisualSnapPoint(map, pendingSnapEventRef.current);
+ });
+ }
queryRenderedFeatures scans the tile renderer on every raw mousemove event (can be 120 fps). With 170k road segments rendered, each call iterates through dozens of features within the 28px snap radius. Wrapped in a requestAnimationFrame guard to cap at 60 fps.
Drawing mode: no coordinate input Editor.tsx + new UI
+ {drawing && (
+ <div style={{ position:"fixed", bottom:46, left:"50%", ... }}>
+ <input placeholder="41.3851, 2.1734" onKeyDown={e =>
+ e.key==="Enter" && handleCoordSubmit(coordInput)} />
+ <button onClick={() => handleCoordSubmit(coordInput)}>Add</button>
+ </div>
+ )}
Added a floating coordinate input that appears only in drawing mode. Accepts lat, lng or lng, lat (auto-detected by magnitude), adds the vertex, pans the map, and clears the field on Enter.
