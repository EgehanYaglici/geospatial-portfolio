01The brief

The client managed a portfolio of sites, each with a high-resolution CAD plan: flat rectilinear rasters, no coordinate metadata, and a need to overlay them on a live Mapbox basemap for field teams. Their existing approach required GDAL on a server, manual coordinate entry, TiTiler, and cloud storage configuration. Per-site turnaround was several hours. Non-technical staff could not do it themselves.

The requirement was a zero-infrastructure solution: load the image in a browser tab, enter four GPS corner coordinates, click export, get a zip of standard Z/X/Y PNG tiles. A second constraint was aliasing: rendering a 22,000 px source directly into a 512 px tile at low zoom levels produces severe Moire patterns. The architecture had to pre-compute a quality pyramid and select the correct tier at render time.

Outcome: The delivered engine reduced the per-site tiling workflow from several hours to under 10 minutes. No installation, no server, no cloud account required. Field staff can now tile a new site themselves from any laptop.

03How the engine works

Three phases run sequentially. Phases 1 and 2 are one-time preparation; Phase 3 is the parallelised tile batch.

1
Homography solve (calculateHomography)
Builds an 8×8 linear system from the 4 GPS corner points (image corners → Web Mercator coordinates). Gaussian elimination extracts the 8 unknown coefficients of the 3×3 projective transform matrix H. This handles any perspective skew in the source image, the 4 corners do not need to form a rectangle.
2
Mipmap pyramid (buildMipmaps)
Uses the Pica.js Lanczos3 kernel to iteratively halve the source image: 1×, 0.5×, 0.25×, … Building the full pyramid takes a few seconds once; the tile render kernel then picks the pyramid level whose native resolution is closest to the target tile scale, eliminating Moiré at low zoom levels.
3
Batch tile export (exportTilesToZip)
Iterates every Z/X/Y coordinate in the requested zoom range. For each tile: (1) bounding-box culling rejects tiles that don't intersect the image, O(1), no render cost; (2) generateTile applies the inverse homography pixel-by-pixel across the 512×512 canvas, bilinear-blending 4 mipmap pixels per output pixel; (3) alpha-culling discards fully transparent tiles; (4) surviving tiles are encoded to PNG and injected into a JSZip archive. Batches of 16 run in parallel via Promise.all() with setTimeout(r, 0) yields to keep the browser responsive.
04The render kernel

The per-pixel loop is the mathematical core. For each pixel (ox, oy) in the 512×512 output tile:

// Target pixel → Web Mercator coordinates const mx = tL + (ox + 0.5) * dxMerc; const my = tT + (oy + 0.5) * dyMerc; // Inverse perspective mapping via homography matrix H const denom = h[6]*mx + h[7]*my + h[8]; const spx = (h[0]*mx + h[1]*my + h[2]) / denom; // source u const spy = (h[3]*mx + h[4]*my + h[5]) / denom; // source v // Bilinear blend of 4 surrounding mipmap pixels const fx = sx - (sx|0), fy = sy - (sy|0); const w00 = (1-fx)*(1-fy), w10 = fx*(1-fy); const w01 = (1-fx)*fy, w11 = fx*fy;

Alpha culling: if the summed alpha across all 512×512 output pixels is zero, the canvas is discarded and null is returned, preventing gigabytes of empty PNG files in the output zip.

05Output format

The zip archive follows the standard Mapbox raster tile directory layout. Drop the extracted folder behind any static file server and point a Mapbox or MapLibre source at it:

map.addSource('enterprise-tiles'{ type: 'raster', tiles: ['path/to/extracted/tiles/{z}/{x}/{y}.png'], tileSize: 512, // CRITICAL, must match engine output minzoom: 9, maxzoom: 22 // hard cap: GSD ~4.8 cm/px at Z22 });
